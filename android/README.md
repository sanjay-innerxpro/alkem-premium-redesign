# Android app

A [Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity) (TWA) that opens the live website full-screen, with no browser address bar. Everything published in the Content Studio (pages, products, news, careers, the Hindi and Urdu versions) appears in the app straight away. You do not need a new app release for content changes.

Built with Google's [android-browser-helper](https://github.com/GoogleChrome/android-browser-helper), the same library Bubblewrap/PWABuilder use. Minimum Android 7.0 (API 24), target Android 16 (API 36).

| What | Where |
| --- | --- |
| App name, domain, app ID, version | `gradle.properties` (`twa.*`) |
| Colours (status bar, splash) | `app/src/main/res/values/colors.xml` |
| Launcher icon, splash logo | `app/src/main/res/mipmap-*`, `drawable-*` (generated by `npm run android:icons`) |
| Play Store icon and feature graphic | `store/` (generated by `npm run android:icons`) |
| Website side | `src/app/manifest.ts`, `src/app/.well-known/assetlinks.json/route.ts`, `public/sw.js` |

## Before you start

1. **The website must be live on HTTPS** at its final domain (for example `www.yourbrand.in`). The app cannot ship before this.
2. **A privacy policy URL is required by Google Play.** The site collects enquiry and career-form data, so publish a privacy-policy page first. The Content Studio can host it as a page, for example `/privacy-policy`.
3. **A Google Play developer account** (one-time US $25, no yearly fee).
   - A **personal** account needs ID and phone verification. It must then run a closed test with at least **12 testers for 14 days in a row** before you can apply for production. Plan for 3–4 weeks.
   - Publish only under a name you own or are authorised to use. Google bans accounts for impersonating a real company. Apps for a real company belong in that company's own **organisation** account (D-U-N-S number required); the company can add you as a user.
4. To build, install [Android Studio](https://developer.android.com/studio) and open this `android/` folder. On the command line you need JDK 17 or 21 (`JAVA_HOME`) and the Android SDK (`local.properties`: `sdk.dir=/path/to/Android/Sdk`).

## 1. Configure

In `gradle.properties`, set `twa.host` to the live domain (no `https://`, no trailing slash). Check `twa.applicationId` (currently `com.nexpharm.healthcare`): **it is permanent once uploaded**, even if the app name changes later, so set your final one before the first upload.

## 2. Create the upload key (once)

```sh
keytool -genkeypair -v -keystore upload-key.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

Store the `.jks` file and both passwords somewhere safe, such as a password manager, and back them up. **Never commit them.** Copy `keystore.properties.example` to `keystore.properties` and fill in the values. That file is gitignored.

## 3. Build the store bundle

```sh
./gradlew bundleRelease
```

Output: `app/build/outputs/bundle/release/app-release.aab`. The build refuses to run while `twa.host` is still the `example.com` placeholder.

## Test APK (before the site is live)

Test builds are called "<app name> Test" and install alongside the store app. They can open any address, including the site running on a computer on the office network:

```sh
npm run build && DEMO_MODE=true npm start   # in the project root; serves on port 3000
./gradlew assembleDebug -Ptwa.testUrl=http://YOUR-COMPUTER-IP:3000/
```

Install `app/build/outputs/apk/debug/app-debug.apk` on a phone on the same Wi-Fi: send the file and allow "Install unknown apps", or run `./gradlew installDebug` over USB debugging. A browser address bar is shown in test builds; that is expected.

## 4. Upload to Google Play

1. Play Console → **Create app** → the app name, type *App*, *Free*.
2. **Release → Testing → Internal testing** → create a release → upload the `.aab`. Accept **Play App Signing** (the default).
3. Complete **App content**:
   - privacy policy URL
   - ads: *No*
   - app access: *All functionality available* (the admin area is not part of the app experience)
   - content rating questionnaire
   - target audience: 18+
   - **Health apps** declaration
   - **Data safety**: the website's enquiry forms collect name, email, phone and message, sent over HTTPS, stored to answer enquiries, not shared, deletable on request
4. **Store listing**:
   - short and full description
   - icon: `store/play-icon-512.png`
   - feature graphic: `store/feature-graphic-1024x500.png`
   - at least 2 phone screenshots, taken from the app on a phone
5. Personal accounts: under **Testing → Closed testing**, add your 12+ testers' Gmail addresses and share the opt-in link. Keep them opted in for 14 days, then use **Apply for production** on the Dashboard.
6. Promote the release to **Production** and submit it for review.

## 5. Link the app to the website (removes the address bar)

Android only opens the site full-screen if the website confirms it owns the app.

1. Play Console → **Test and release → App integrity → App signing**. Copy the **SHA-256** fingerprints of both the *app signing key* and the *upload key*. For test APKs, also add the debug key's fingerprint: `keytool -list -v -keystore ~/.android/debug.keystore -storepass android | grep SHA256`.
2. Set these on the **web server's** environment, then restart the site:

   ```dotenv
   ANDROID_PACKAGE_NAME=com.nexpharm.healthcare,com.nexpharm.healthcare.test
   ANDROID_SHA256_FINGERPRINTS=AA:BB:...:FF,11:22:...:99
   ```

3. Check that `https://YOUR-DOMAIN/.well-known/assetlinks.json` returns the JSON. It returns 404 until both variables are set. Then reopen the app; the address bar is gone.

## Changing the name

The name lives in **Content Studio → Website settings → Brand name** (and Brand tagline). The website copy says `{brand}` wherever the name appears, in all three languages. Saving a new name updates every page, the logo letter, the favicon and the install icon at once.

The Android app carries its own copy of the name and icons, so after a rename:

1. Set `twa.appName` in `gradle.properties` to the same name.
2. With the website running, run `npm run android:icons` (or `npm run android:icons -- https://your-domain`) from the project root. It downloads the launcher icon, splash logo and Play Store graphics from the site.
3. Build and upload an app update (below), and change the name in the Play Store listing.

The app ID (`twa.applicationId`) cannot change once the app is on Google Play.

## Releasing an app update

You only need this for changes to the app itself, such as the name, icon, colours, domain or library version, never for website content. Increase `twa.versionCode` by 1 (and `twa.versionName`), run `./gradlew bundleRelease`, and upload a new release in Play Console.
